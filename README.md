# KikuFrame：AI 日语视频学习工具

> 把日语视频转换成可点击、可循环、可纠错、可分析的逐句学习材料。

## 为什么要做这个程序

视频平台提供的人工字幕和自动字幕经常与实际说话内容不完全一致，尤其容易出现漏字、
错字、断句错误和时间轴偏移。

很多视频已经把更准确的字幕直接烧录在画面里，但这类字幕属于视频图像的一部分，无法
像普通字幕一样复制或下载。KikuFrame 从视频画面中识别烧录字幕，结合视频平台字幕作为
读音参考，再把字幕和音频整理为适合日语学习的互动材料。它的目标不只是导出 Markdown，
而是让学习者能够逐句听、反复听、修正断句，并查看词汇、搭配、读音和文法分析。

## 有什么效果

输入一个公开的 YouTube 视频 URL 后，KikuFrame 会：

1. 使用 `yt-dlp` 获取视频信息并下载包含音轨、适合识别的视频流。
2. 使用 FFmpeg 从画面底部的默认字幕区域抽取视频帧。
3. 筛选字幕发生变化的关键帧，减少重复的云端请求。
4. 调用用户提供 API Key 的 OpenAI-compatible 视觉模型识别烧录字幕。
5. 下载同语言的 YouTube 人工字幕或自动字幕，作为说话内容和读音参考。
6. 让文本模型综合 OCR 置信度、候选字、前后文和 YouTube 读音参考纠正错字；大幅
   增删或跨字幕段搬运文字的建议会被安全拦截。
7. 综合文本模型的语义判断与高匹配 YouTube 句界，支持在字幕片段内部断句。
8. 保存视频音频，并输出三个以视频标题命名的 Markdown 文件。
9. 在本地界面中一句一行显示整理后的字幕；点击句子即可从对应时间播放音频。
10. 支持当前句循环、手动断句纠错，以及语言学习模型的单句分析。

```text
output/
├── 视频标题.md                       # 原始 OCR：包含 metadata、来源和时间戳
├── 视频标题（综合校正版）.md         # OCR + YouTube 读音参考，包含时间戳
├── 视频标题（综合校正版）（整理版）.md # 只保留一句话一行的字幕
└── 视频标题.m4a                      # 供保存和字幕播放器使用的音频
```

如果没有填写文本模型，程序会默认复用视觉模型。假如视觉模型无法处理纯文本，原始版
仍然会保留并出现在前端；补填文本模型后再次提交同一视频，程序会直接复用原始版，不
重新下载视频、抽帧或执行视觉 OCR。同一视频通过 YouTube 视频 ID 判断，因此 URL 中
不同的 `?si=` 参数不会影响复用。

处理失败时，前端会停止转动动画、显示 `❌`，恢复提取按钮并说明失败原因。任务历史、
OCR 检查点和语义断句检查点都会保存在本机，意外中断后可以继续。已经由旧版本
提取过字幕但没有音频时，新版本只补充下载和保存音频，不会重新运行视觉 OCR。

## 如何安装

### macOS

1. 在 GitHub 项目页面点击 **Code → Download ZIP**，下载后解压。
2. 安装 Homebrew，并安装运行环境：

```bash
brew install python@3.12 ffmpeg deno
```

3. 项目不需要安装 PaddleOCR。第一次启动时，启动脚本会在项目内部创建 `.venv`
   虚拟环境并安装所需 Python 依赖。

如果 macOS 没有保留脚本的执行权限，在项目目录运行一次：

```bash
chmod +x start-submd.command uninstall-submd.command
```

### Windows

1. 下载并解压 GitHub ZIP。
2. 安装 Python 3.12、FFmpeg 和 Deno，并确保三者已经加入 `PATH`。
3. 第一次启动时，`start-submd.bat` 会在项目内部创建虚拟环境并安装 Python 依赖。

项目附带 `.env.example`，但不需要提前手动创建 `.env`；第一次在前端保存配置时会
自动生成。`.env` 已被 Git 忽略，不会随正常提交上传到 GitHub。

## 如何启动

### macOS

双击：

```text
start-submd.command
```

如果 macOS 首次阻止打开，可以右键该文件并选择“打开”。启动成功后会用 Chrome 打开：

```text
http://127.0.0.1:8765
```

字幕处理期间需要保持启动脚本的终端窗口开启。

### Windows

双击：

```text
start-submd.bat
```

也可以在已经创建虚拟环境的项目目录中手动启动：

```bash
.venv/bin/submd ui
```

## 如何使用

在前端填写：

- **YouTube 视频 URL**：单个公开 YouTube 视频地址。
- **OCR API Base URL**：云厂商提供的 OpenAI-compatible API 地址，例如
  `https://厂商地址/v1`。
- **视觉模型名称**：能够接收图片的模型名称。
- **API Key**：云厂商提供的密钥，只保存在本机 `.env`。
- **浏览器 Cookie**：YouTube 要求登录验证时填写 `chrome`；请先在 Chrome 中登录
  YouTube。
- **文本模型地址和名称（可选）**：用于语义断句；留空时复用 OCR 地址和视觉模型。
- **语言学习模型（可选）**：用于播放器里的单句分析；地址、模型和 API Key 留空时，
  会依次复用整理模型与 OCR 配置。

点击“提取字幕”后，页面会显示当前阶段。成功时会出现原始 OCR、YouTube 读音参考
综合校正版、整理版和音频文件，并自动打开字幕音频播放器，同时写入提取历史。如果
YouTube 没有可用字幕，程序会明确提示并继续使用 OCR 与语义模型，不会因此丢失结果。

播放器会一句一行显示整理后的字幕。点击任意一句，音频会跳到该句烧录字幕首次出现
的时间并播放；播放过程中当前句会自动高亮和滚动。也可以使用“上一句”和“下一句”
切换。打开“单句循环”后，音频会在当前句的开始和结束时间之间反复播放。这里采用
句子级时间对齐，不需要 ASR，也不进行逐单词对齐。

需要修正前后句边界时，长按任意句子进入断句纠错，再点击另一句即可连续选择这一范围；
也可以先点击一句播放，再点播放器控制栏里的“断句纠错”。点击“修改断句”后，只需在
弹窗里增删或移动句号“。”，下方会立即按一行一句预览。保存时程序会优先回到 OCR/综合
校正字幕段的原始时间轴，将新句界映射到对应字符位置，并同步更新播放器与整理版
Markdown。所有修改保存在本机，历史记录位于 `workspace/manual-edits/`。

每个句子右下角都有“分析”按钮。点击后，语言学习模型会给出整句中文翻译、所有主要
词汇与词组搭配的中文释义，以及本句文法说明；包含日文汉字的词汇会标注平假名读音。
分析弹窗大小固定，内容较多时可以在弹窗内滚动。结果缓存在 `workspace/learning/`，同一
模型对同一句子的重复分析会读取缓存，不重复调用 API。弹窗内的“重新分析”会强制调用
模型，并在成功后覆盖该句的旧缓存；如果重新分析失败，原缓存仍然保留。

如果只生成了原始版，说明语义断句模型调用失败。此时展开“整理版字幕模型”，填入可
处理纯文本的模型，再用相同视频 URL 提交。程序会跳过视觉 OCR，直接从已有原始
Markdown 生成整理版。

视频帧会发送到用户配置的云厂商进行 OCR；API Key、浏览器 Cookie 和 `.env` 不会
写入 Markdown 或 JSON 中间结果。默认字幕区域是画面底部 35%，需要其他区域时可以
通过 CLI 的 `--roi "x,y,width,height"` 参数调整。

## 如何删除

### macOS 一键删除

1. 关闭 KikuFrame 页面和运行它的终端窗口。
2. 双击：

```text
uninstall-submd.command
```

3. 在确认窗口点击“移到废纸篓”。

脚本会进行项目标记检查，停止由当前项目启动的 8765 本地服务，然后将整个项目文件夹
移入废纸篓。项目代码、`.env`、API Key、字幕结果、缓存、检查点和 `.venv` 会一起
移除；系统中的 Python、FFmpeg 和 Deno 不会被删除。清空废纸篓后才是永久删除。

### Windows

关闭 KikuFrame 窗口和终端后，删除整个项目文件夹即可。虚拟环境、配置、缓存和输出都在
项目文件夹内，没有注册系统服务或浏览器扩展。

## 项目结构、架构和各单元功能

```text
YouTube URL
    │
    ▼
网页 UI ──► 本地任务服务
              │
              ├──► YouTube 获取层：元数据、Cookie、视频下载
              ├──► 读音参考层：人工/自动字幕选择、JSON3/VTT 解析、时间对齐
              ├──► 媒体层：ffprobe、FFmpeg 抽帧、ROI 裁切、关键帧筛选、音频导出
              ├──► 云 OCR 层：图片编码、API 请求、重试、响应校验
              ├──► 字幕 Pipeline：检查点、相邻帧去重、时间段合并
              ├──► Markdown 导出：原始字幕文件
              ├──► 综合纠错器：OCR + 读音参考、检查点、安全改写拦截
              ├──► 语义整理器：字符级断句、YouTube 句界锚点、字符守恒、时间映射
              ├──► 手动纠错器：连续选句、句号重排、音频时间重算和编辑历史
              ├──► 学习分析器：单句翻译、词汇读音、搭配和文法分析、本地缓存
              └──► 字幕播放器：音频 Range 传输、点击跳转、循环播放、当前句高亮
```

```text
kikuframe/
├── start-submd.command       # macOS 一键启动
├── start-submd.bat           # Windows 一键启动
├── uninstall-submd.command   # macOS 一键移入废纸篓
├── .env.example              # 外部变量示例，不包含真实密钥
├── pyproject.toml            # Python 版本、依赖、CLI 和打包配置
├── src/submd/
│   ├── cli.py                # `submd extract`、`submd organize`、`submd ui` 命令入口
│   ├── web.py                # 本地 HTTP 服务、后台任务、历史、播放器 API 和音频传输
│   ├── ui/
│   │   ├── index.html        # 前端页面与字幕音频播放器结构
│   │   ├── styles.css        # 页面、进度、字幕列表和当前句高亮样式
│   │   └── app.js            # 配置、轮询、弹窗、点击跳转和播放同步
│   ├── youtube.py            # yt-dlp 视频下载、Cookie、YouTube 字幕选择与解析
│   ├── media.py              # ffprobe、FFmpeg 抽帧、音频保存、ROI 和图像变化筛选
│   ├── ocr/
│   │   ├── base.py           # OCR 引擎统一接口
│   │   └── openai_compatible.py
│   │                         # 视觉模型请求、图片压缩、限流重试和 JSON 校验
│   ├── pipeline.py           # 下载到导出的主流程和断点恢复
│   ├── segments.py           # 相邻帧文本相似度、去重和字幕时间段合并
│   ├── fusion.py             # OCR 与 YouTube 读音参考综合纠错、检查点与安全闸
│   ├── organize.py           # 字符级语义断句、参考句界与句子时间映射
│   ├── editing.py            # 手动句号断句、字符时间映射与音频重新对齐
│   ├── learning.py           # 语言学习模型请求、单句结构化分析和结果缓存
│   ├── exporters.py          # 安全文件名和原始 Markdown 导出
│   ├── models.py             # Pydantic 配置与领域数据模型
│   ├── json_io.py            # JSON 检查点的安全写入
│   ├── text.py               # OCR 文本规范化
│   └── errors.py             # 下载、媒体、OCR、整理等错误类型
├── tests/                    # 下载器、OCR、Pipeline、整理器和网页 UI 自动化测试
├── workspace/                # 运行时生成：视频级 JSON、预览、缓存和检查点
└── output/                   # 运行时生成：两个 Markdown 和 M4A 音频
```

`workspace/` 中的 `segments.json` 始终保留原始 OCR 合并结果，`youtube_captions.json`
保存独立的读音参考轨，`corrected_segments.json` 保存可追溯的综合校正结果；三者不会
互相静默覆盖。`organized_segments.json` 保存每句话的 `start_ms`、`end_ms` 和来源字幕
段，供播放器使用；纯字幕 Markdown 仍然只包含文字。`workspace/`、`output/`、`.env`
和 `.venv` 均不会进入正常 Git 提交。
